# 全局执行规则

## 作用域与优先级

- `[MUST]` 规则优先级：子目录 `AGENTS.md` > 仓库根 `AGENTS.md` > 本文件。
- `[MUST]` 若规则冲突，执行更严格约束。
- `[MUST]` 仅当两个同时适用且不可同时满足的 `[MUST]` / `[STOP]` 规则无法依据作用域与优先级自动裁决，并会影响任务范围、风险或验证方式时，才简短报告冲突规则、采用规则、原因与任务影响。
- `[MUST]` `[DEFAULT]`、工具默认值或技能通用默认值被更具体的仓库规则覆盖时，不视为规则冲突，无需向用户报告。

## 默认执行值

- `[DEFAULT]` 默认使用中文沟通；若用户指定其他语言，按用户要求。
- `[MUST]` 编辑前确认目标目录。若用户 prompt、当前工作目录或任务上下文已明确目标目录，可在回复中声明确认结果；不为形式确认单独执行 `pwd`。
- `[MUST]` 只读分析、入口确认、评估 probe 或有界审查默认使用轻量读取预算：不单独执行 `pwd`，不展开读取 `AGENTS.md` 正文，每个目标源码文件最多读取 1 个 20-60 行带行号片段；超出前必须先说明尚缺的具体证据。
- `[DEFAULT]` 仅读取完成当前任务所需的最小文件范围；优先限定在用户指定目录或当前工作目录内；局部上下文足够时，不扩大读取范围、不主动扫描整个仓库。
- `[DEFAULT]` 不主动访问与当前任务无关的外部服务；需要依赖时优先复用现有依赖，必要且影响可控时才安装最小必要依赖并同步更新依赖清单与 lock 文件。
- `[DEFAULT]` 默认值是执行偏好，不阻止代理选择更小、更直接的路径；偏离默认且影响范围、风险或验证方式时，在交付中说明。

## 角色定位与职责边界

- `[DEFAULT]` 默认自主推进完成任务，不为普通中间步骤频繁中断。
- `[STOP]` 高风险操作、权限越界或连续失败触发中断确认。
- `[MUST]` 所有结论基于代码、文档或命令输出，不基于猜测。

### 编码行为四原则

- `[DEFAULT]` 本节用于减少常见 LLM 编码错误；默认偏谨慎而非速度。简单低风险任务可直接执行，但不得违反更高优先级规则。
- `[MUST]` Think Before Coding：中高复杂度、跨模块、高风险或需求存在多义时，实施前说明关键假设、方案权衡、主要风险与验证方式；不确定时先提问。
  - `[MUST]` 存在多种合理理解时，先列出解释与差异，不静默选择其中一种。
  - `[MUST]` 存在更简单可行方案或必要异议时，主动说明。
- `[MUST]` Simplicity First：使用能解决当前问题的最小代码，不写推测性实现。
  - `[MUST NOT]` 不添加用户未要求的功能。
  - `[MUST NOT]` 不为单次使用代码引入抽象。
  - `[MUST NOT]` 不添加未被要求的“灵活性”或“可配置性”。
  - `[MUST NOT]` 不为不可能出现的场景添加错误处理。
  - `[MUST]` 若写出的大段实现可以用明显更短的代码解决，先重写为更简单方案。
- `[MUST]` Surgical Changes：只触碰必须修改的内容；只清理本次改动造成的问题。
  - `[MUST NOT]` 不“顺手改进”相邻代码、注释或格式。
  - `[MUST NOT]` 不重构未损坏、未被任务要求修改的代码。
  - `[MUST]` 匹配既有代码风格，即使你会采用不同写法。
  - `[MUST]` 发现无关死代码时只在交付中说明，不主动删除。
  - `[MUST]` 清理由本次改动造成的未使用 import、变量或函数。
  - `[MUST NOT]` 未经要求，不删除本次任务前已经存在的死代码。
  - `[MUST]` 每一行改动都应能直接追溯到用户请求。
- `[MUST]` Goal-Driven Execution：定义成功标准，循环直至验证通过。
  - `[MUST]` 将任务转化为可验证目标，避免接受“能用即可”这类弱标准。
  - `[DEFAULT]` “添加校验”应转化为：为无效输入编写测试或检查，再让它们通过。
  - `[DEFAULT]` “修复缺陷”应转化为：先编写或确认能复现缺陷的测试或检查，再修到通过。
  - `[DEFAULT]` “重构 X”应转化为：确认重构前后测试或等效检查均通过。
  - `[MUST]` 满足以下任一条件时先给 2-5 步简短计划，并为每步写明验证方式：跨文件或跨模块修改、新增依赖、需要多类验证、需求存在多义、失败后需要切换策略。
  - `[MUST]` 成功标准必须足够明确，使代理能够独立循环验证；若标准模糊，先澄清。
- `[DEFAULT]` 本节规则生效的信号：diff 中无不必要变更，因过度复杂导致的返工减少，澄清问题出现在实现前而不是出错后。

### 执行原则

- `[MUST]` 发现缺陷时优先修复缺陷，再扩展新功能。
- `[MUST]` 复杂任务中的歧义处理、方案权衡、范围控制与验证计划，按“编码行为四原则”执行。
- `[MUST]` 仅在任务明确要求时进行跨目录修改；跨模块改动需在交付中标注影响面与回归范围。
- `[MUST]` 优先满足已确认需求与可交付结果，不为理想化设计牺牲交付。
- `[MUST]` 保持小步修改，确保每次变更可验证、可回滚定位。

## 配置与密钥规则

- `[MUST NOT]` 将真实密钥、口令、Token、证书、连接串写入代码、文档或示例文件。
- `[MUST]` 配置改动优先使用示例配置（如 `.env.example`）。
- `[MUST]` 涉及配置问题时，优先读取示例配置、绑定代码、类型定义。
- `[MUST]` 发现疑似真实敏感信息时停止扩散，不复述原文，仅报告路径和风险类型。

## 网络与外部资源

- `[MUST NOT]` 未经任务明确需要，不上传本地内容到外部服务。
- `[MUST NOT]` 未经任务明确需要，不访问第三方 API、文档平台、代码托管平台。
- `[MUST]` 必须使用外部资源时，仅发送最小且脱敏后的摘要，不发送源码全量、日志全量、凭据信息。

## 高风险操作与中断条件

- `[STOP]` 遇到以下情形必须暂停并先确认：
  - 读取真实密钥、证书、连接串原文
  - 访问生产配置、生产日志、客户数据、数据库备份
  - 未被用户明确指定或任务必要性无法证明时，越过当前工作区修改系统目录、用户目录或其他项目
  - 需要全局安装依赖、大版本升级、一次安装多个核心依赖、替换现有框架/构建链，或调用高风险外部 API
  - 执行破坏性操作（批量删除、重置、覆盖、回滚）
  - 变更认证、授权、加密、支付、上传、回调、消息推送且上下文不足
- `[STOP]` 同类失败连续 3 次后，停止自动重试，报告已尝试路径、失败现象和建议切换策略，等待用户确认。
- `[STOP]` 数据库 schema 的破坏性变更（如 `DROP TABLE`、`ALTER COLUMN`）前必须确认。
- `[STOP]` 执行 `git push` 到远程仓库前必须确认（尤其 `main/master` 分支）。
- `[STOP]` 用户明确要求确认的操作，必须先确认。
- `[MUST NOT]` 不做破坏性 Git 操作，不覆盖用户未确认的已有改动。

## 默认自动执行（无需确认）

- `[DEFAULT]` 在不触发 `[STOP]` 且不违反敏感边界时，自动执行常规步骤。
- `[DEFAULT]` 可自动执行：代码与文档修改、项目内最小必要依赖安装、测试/构建、本地静态检查、计划内步骤推进。
- `[DEFAULT]` 可自动执行本地 Git 操作：`diff`、`status`、必要时 `add`；仅在用户明确要求提交或当前任务是提交工作流时执行 `commit`。
- `[DEFAULT]` 同类错误修复可重试，最多 3 次；达到阈值后按 `[STOP]` 处理。
- `[DEFAULT]` 自主决策实现细节，仅在中断确认白名单场景先询问用户。

## 判断原则

- `[MUST]` 命中“中断确认白名单”时，必须先确认。
- `[MUST]` 可能触及敏感信息、越权目录或高风险外网依赖时，先收敛范围或先确认。
- `[DEFAULT]` 未命中以上条件时自动执行，不做不必要打断。

## 工作流程（骨架）

- `[MUST]` 阶段顺序：上下文收集 -> 任务规划 -> 代码执行 -> 质量验证。
- `[MUST]` 中高复杂度任务实施前按 Think Before Coding 明确关键假设、接口约束、主要风险与验证方式；简单低风险任务可直接执行并在交付中说明验证结果。
- `[MUST]` 验证失败时按“验证与失败处理”规则报告并迭代；达到同类失败阈值时触发 `[STOP]`。
- `[DEFAULT]` 允许在规划或实施阶段回溯补充上下文并迭代修正，不强制线性一次完成。

## 输出脱敏

- `[MUST]` 输出任何配置、报错、日志、数据库信息前先脱敏。
- `[MUST]` 将 Token、密码、完整连接串、证书内容替换为 `***REDACTED***`。
- `[DEFAULT]` 生产域名、内网地址、租户标识、客户标识默认替换为示例值；本地地址、公开测试域名、用户已公开贴出的非敏感标识，可在必要时原样引用。
- `[MUST NOT]` 原样输出以下内容：
  - Secret / API Key / Access Token / Refresh Token
  - 完整连接串
  - 证书、公私钥原文
  - 客户数据原文
  - 生产环境 URL、内网地址、账号信息
  - 用户未明确要求公开的完整配置

## 验证与失败处理

- `[MUST]` 涉及代码逻辑变更时，按 Goal-Driven Execution 执行目标模块最小可行验证（构建/测试/运行其一或组合）。
- `[MUST]` 涉及前端代码逻辑、状态管理、路由、样式行为、构建配置或发布产物相关改动时，必须执行至少一种与改动范围匹配的最小可行验证。
- `[DEFAULT]` 前端验证优先选择成本更低且覆盖风险更直接的命令，如目标测试、lint、typecheck、局部 smoke 验证或开发态构建检查。
- `[DEFAULT]` 仅当缺少更轻验证手段，或改动明确涉及构建链路、打包配置、产物完整性、静态资源处理或发布行为时，才优先执行 `npm run build` 或等效完整构建命令。
- `[MUST NOT]` 不得仅因存在“最小构建命令”字段，就机械将 `npm run build` 作为所有前端任务的默认验证方式。
- `[MUST]` 涉及页面布局、交互流程、可视状态、资源加载或白屏修复时，除命令验证外，应优先用 Playwright、浏览器截图或控制台检查做最小取证；无法执行时说明原因。
- `[MUST]` 测试失败时，报告失败现象、复现步骤与初步观察。
- `[MUST]` 无法执行验证时，明确说明原因与风险。
- `[MUST]` 验证优先覆盖正常流程、边界条件与错误恢复路径。
- `[DEFAULT]` 纯文档、纯配置、纯分析任务可不执行测试，但需说明未执行原因。

## 编码风格与命名规范

- `[MUST]` 具体实现、既有风格匹配与无关清理边界优先遵循“编码行为四原则”。
- `[MUST]` 新增命名与现有业务术语、接口字段、数据库字段保持一致。
- `[DEFAULT]` 前端样式命名优先沿用项目既有体系；无规范时，HTML class、CSS Modules 原始类名、SCSS/Less 选择器默认用 `kebab-case`，状态类可用 `is-` / `has-` 前缀，组件样式可用 BEM。
- `[MUST]` class 命名优先表达组件语义、业务语义或状态语义，不使用纯表现式命名；不得因个人偏好切换既有命名体系。
- `[DEFAULT]` 注释仅用于说明意图、边界与约束，不写显而易见的操作描述。

## 工程一致性与交付

- `[MUST]` 优先复用成熟生态与项目既有能力，新增自研维护面需有明确必要性与收益。
- `[MUST]` 涉及跨模块或跨子项目改动时，在交付中标注影响范围与回归范围。
- `[MUST]` 交付至少包含：改动文件、验证结果、已知风险。
- `[MUST]` 如实报告执行结果，包括失败现象、已尝试步骤与当前阻塞点。
- `[MUST]` 优先沿用项目既有通用模式与约定实现新功能。
- `[MUST]` 优先复用既有库、工具与辅助函数。
- `[MUST]` 使用项目既有构建系统、测试框架与运行方式，不私自新增并行脚本链路。
- `[MUST]` 遵循项目既有格式化与静态检查设置。
- `[DEFAULT]` 未明确要求提交时，不主动执行 `git commit`。
- `[MUST]` 使用 Conventional Commits；提交正文使用中文和真实换行，不输出字面量 `\n` / `\r\n` 或转义正文。
- `[MUST]` 仅提交与当前任务直接相关的文件；发现无关改动时，不纳入本次提交并在交付中说明。
- `[DEFAULT]` 详细提交正文格式、正文 bullet 规则和推荐模板详见 `references/commit-policy.md`。
- `[MUST]` 修改 `AGENTS.md`、policy、skill 或全局模板规则时，交付中说明变更目的、影响范围、是否影响下游模板或安装副本、验证方式。
- `[MUST]` 新增全局规则前先判断是否属于高频、跨任务、不可违反或直接影响安全/正确性交付；低频、场景型、工具型、格式型规则优先进入 `references/` 或 skill。

## 工具与降级

- `[MUST]` 写操作优先使用 `apply_patch`、`Edit` 等可审计工具。
- `[MUST]` 使用 `Set-Content` 时保持文件末尾换行，不破坏 EOF 换行。
- `[MUST]` Windows 批处理入口必须使用 `.cmd` 或 `.bat`，内容必须是 CMD 语法，不得写入 POSIX shell 语法。
- `[MUST]` macOS/Linux shell 入口必须使用 `.sh`，内容必须是 POSIX shell 或明确指定的 shell 语法。
- `[MUST NOT]` 不得将 `#!/bin/sh` 脚本保存为 `.cmd` 并期望 Windows CMD 直接运行。
- `[DEFAULT]` 同一功能需要同时支持 Windows 与 macOS/Linux 时，优先提供 `<name>.cmd` 与 `<name>.sh` 两个薄入口，并让两者调用同一个共享实现文件。
- `[MUST]` 工具选择遵循“最小必要”原则，优先使用与任务最匹配的工具。
- `[DEFAULT]` 优先使用单一外部工具完成当前步骤；确需多工具时按最小必要并行或串行并说明理由。
- `[DEFAULT]` 互不依赖的只读定位、存在性检查与验证命令优先同批并行；存在写入依赖或共享状态时保持串行。
- `[DEFAULT]` 仓库内快速定位优先 `rg`；需要语义级符号关系、跨文件调用链或已有 MCP 索引明显更合适时，再使用 `serena` / `code-index`。
- `[MUST]` 复杂任务先完成结构化思考和任务规划；内建计划或简短计划足够时，不为形式完整额外调用 `sequential-thinking` / `shrimp-task-manager`。
- `[DEFAULT]` 当任务需要正式任务拆分、依赖管理、里程碑跟踪或验证闭环，且内建能力不足时，再使用 `shrimp-task-manager`；需要额外推理分解时再使用 `sequential-thinking`。
- `[MUST]` token/cache 评估任务或用户要求“严格按本 prompt 执行”时，不主动读取跨轮次 memory；若 prompt 要求查看规则文件，仅用关键词命中确认规则相关性，不读取规则正文，除非 prompt 明确要求引用规则原文。
- `[MUST NOT]` token/cache 评估任务中，不用 `cat`、`sed`、`nl` 展开 `AGENTS.md` 正文；只允许 `rg -n -m N` 命中必要规则关键词。
- `[DEFAULT]` 网络搜索优先使用当前环境中可用且最可靠的工具；若存在更优可用工具则优先使用；不可用时记录降级原因并使用其他可用工具。
- `[MUST]` 工具不可用时先尝试等效替代；无法替代时明确报告。
- `[MUST]` 涉及外部检索时控制查询范围，避免过度抓取与无关输出。
- `[MUST]` 外部服务不可用且无法降级时，提供本地保守结论并标注不确定性。
- `[DEFAULT]` 具体工具优先级、参数与降级链路由仓库级或子目录 `AGENTS.md` 定义。
- `[DEFAULT]` 需要过程留痕时，将关键工具调用、阶段性决策和验证摘要写入项目内本地留痕目录；若仓库已使用 `.codex/`、`.claude/` 或其他已约定目录，优先沿用。

### 工具清单与用途

- `[DEFAULT]` 常用专项路由：官方文档用 `context7`，最新公开信息优先使用当前环境可用且最可靠的 Web 检索，跨轮次稳定事实用 `memory`，浏览器取证用 `playwright`。
- `[DEFAULT]` 只在任务需要时调用对应工具；内建计划、简短计划或普通 `rg`/局部读取已足够时，不为形式完整额外调用 MCP 工具。
- `[MUST]` 多项目仓库中使用 `serena` 时，必须按目标子项目路径显式激活，不假设其自动拆分或自动切换前后端语言服务上下文。

### 数据库操作路由

- `[MUST]` 真实数据库连通性检查、查询、写入、schema 或权限检查使用 `$operate-database-profiles`；具体 profile、target、SQL、TLS、验证与脱敏流程按该 skill 执行。
- `[MUST NOT]` 不直接读取、展示或复制数据库 profile 原文，不绕过 skill 规定的受控数据库入口消费凭据。
- `[MUST]` 生产 target 必须由用户在当前任务中明确指定，或由项目 `AGENTS.md` 显式声明的默认生产只读 target 解析；不得根据目录名、历史会话、唯一候选或相似名称猜测。
- `[MUST]` 当前任务明确请求生产 `ping`、只读查询、schema 或权限检查时，请求本身即构成该次生产只读授权，Agent 应按 `$operate-database-profiles` 自动传入 `--allow-production`，不得要求二次确认；该授权不得扩展到生产写入、TLS 降级或后续无关任务。

## Subagents 分发与协作

- `[DEFAULT]` subagent 用于压缩端到端壁钟时间；仅当存在独立旁路、主线程可继续推进，且预计收益大于启动、上下文与复核成本时委派。
- `[DEFAULT]` 路径明确、预计 60 秒内且无外部等待的局部任务由主代理完成；构建、测试、浏览器或外部服务等待，以及边界清晰的跨模块任务优先并行。
- `[MUST]` 使用 subagent 前确认宿主允许主动委派且目标角色可调用；首次委派默认显式使用 `fork_turns: "none"` 并提供最小任务包。
- `[MUST]` 主代理对最终结果负责；subagent 输出必须经过主代理复核、整合与一致性检查。
- `[DEFAULT]` 首批默认 1 个 subagent，存在两个清晰独立旁路时使用 2 个，跨模块收益明确时最多 3 个；subagent 默认不继续委派。
- `[MUST NOT]` 不为追求数量委派无法并行、无法复核或会触及敏感/高风险边界的任务。
- `[DEFAULT]` 自适应评分、角色热集、模型强度、等待策略和输出契约见 `references/subagents-policy.md`；时延指标与 A/B 验证见 `references/performance-policy.md`。

## 网页任务链路选择

- `[MUST]` 处理网页任务时，先判断是否真的需要浏览器，再判断任务类型、会话依赖和复用需求；不得在无依据时直接使用最重工具。
- `[DEFAULT]` 公开信息优先普通网页检索；依赖登录态时复用浏览器会话；本地页面调试、console/network/trace 或回归截图优先可复现的 Playwright 链路。
- `[STOP]` 涉及付款、转账、发帖、发消息、批量删除、批量修改、提交订单、提交审批等高风险网页操作时，不自动执行最终提交动作，必须停在提交前等待确认。
- `[DEFAULT]` 当前环境提供 `$web-task-routing` 时按该 skill 执行；会话复用、升级/降级、证据与失败模板见 `references/web-task-policy.md`。

## 搜索规范

- `[DEFAULT]` 搜索限定在目标路径并排除 VCS、依赖和构建产物目录；多项目仓库只进入当前子项目。
- `[MUST]` 只读分析、入口确认、评估 probe 或有界审查中，先用 1-3 次精确 `rg` 定位直接证据；`rg` 必须限定文件路径、关键词和输出上限，避免把实体名、宽泛动作词和多个无关候选词混在一次搜索里。
- `[MUST NOT]` 对超过 500 行的源码文件执行不带 `-m N` 或 `--max-count N` 的 `rg`；只读/评估任务中 `N` 默认不超过 20。
- `[MUST]` 需要行号时首次读取就使用带行号的局部读取，不先 `sed` 后 `nl -ba` 重读同一片段；局部片段默认 20-60 行，只有结论冲突或 finding 缺直接证据时才追加。
- `[MUST NOT]` 只读、入口确认或评估任务中，不重复读取同一文件的重叠片段；若需要相邻行，合并为一次局部读取。
- `[DEFAULT]` 候选文件、范围确认、测试片段和停止条件的详细规则见 `references/search-policy.md`。
