# Subagents 分发与协作专项规则

## 适用范围

- `[MUST]` 使用 subagent 前，先确认当前宿主环境允许主动委派；若宿主或平台限制为“仅用户明确要求时可委派”，该限制优先。
- `[MUST]` 不假设系统会自动选择、匹配或拉起 subagent；需要使用时必须显式委派。
- `[MUST]` 项目内 `.codex/agents/` 与宿主全局代理同名时，优先使用项目级定义。
- `[MUST]` 委派前先完成够用的最小本地上下文收集：目标、影响范围、关键路径、可并行部分、验证方式；不得为追求完整上下文推迟明显可并行的只读或验证旁路。
- `[MUST]` 主代理对最终结果负责；subagent 输出必须经主代理复核、去重、冲突裁决和一致性整合。

## 分发决策

- `[MUST]` 先判断任务类型：实现、调试、审查、验证、文档、规划或混合。
- `[MUST]` 混合任务必须区分“执行职责面”和“验证或审查职责面”；职责面可以由主代理本地完成，不等同于必须增加 subagent。
- `[MUST]` 分发目标优先是压缩端到端壁钟时间，其次是提升覆盖率或专业判断质量；subagent 启动率仅作为诊断指标。
- `[MUST]` 仅当存在独立旁路、主线程可继续推进，且预计节省时间大于启动、上下文传递、等待和复核成本时委派。
- `[MUST NOT]` 不得把关键路径整体外包后空等；主代理应优先推进当前阻塞路径，把旁路审查、验证、文档或补充分析交给 subagent。
- `[DEFAULT]` 路径明确、预计 60 秒内完成且没有外部等待窗口的单文件或单逻辑块任务，由主代理本地完成。
- `[DEFAULT]` 详细时延目标、任务分档、工具批处理与度量方法见 `references/performance-policy.md`。

### 自适应触发矩阵

- `[DEFAULT]` 需要运行测试、构建、lint、typecheck、浏览器验证或外部命令等待时，在等待开始前一次性启动 1 个有界只读旁路；若主线程没有可并行工作，则不为形式委派。
- `[DEFAULT]` 跨模块、跨项目、前后端或代码与文档同步任务，在共享契约稳定且所有权可划分时启动 1-2 个 subagents。
- `[DEFAULT]` 需要比较多个独立候选入口、方案、版本或数据来源时，将候选证据收集分给 1-2 个只读 subagents。
- `[DEFAULT]` review、audit、安全、性能或可访问性检查仅在范围、风险或独立审查价值足以覆盖调度成本时委派；范围很小时由主代理本地完成。
- `[DEFAULT]` 排障先由主代理推进最短复现或故障链；日志、配置和代码链路互不依赖时，再委派单一证据主题。
- `[DEFAULT]` 纯问答、即时单步命令、预计 60 秒内的明确局部任务、强串行调试，以及无法脱敏的敏感边界默认不委派。

### 快速评分

分发前按收益项加分、成本项减分：

| 维度 | 0 | 1 | 2 |
| --- | --- | --- | --- |
| 并行性 | 无清晰旁路 | 一个独立旁路 | 多个独立职责面 |
| 等待窗口 | 无等待 | 一次短等待 | 构建、测试、浏览器或外部服务长等待 |
| 范围 | 单文件或单一逻辑块 | 少量文件 | 跨模块或跨目录 |
| 不确定性 | 路径明确 | 需要定位或权衡 | 多假设冲突或根因未收敛 |
| 上下文重复成本（减分） | 最小任务包 | 需要多个近期回合 | 需要完整长会话或同背景广播 |
| 合并复核成本（减分） | 只读结论 | 少量独立写入 | 共享文件、共享状态或高冲突路径 |

- `[DEFAULT]` 总分不高于 0：主代理本地完成。
- `[DEFAULT]` 总分 1-2：采用“一主一辅”，辅线程默认只读。
- `[DEFAULT]` 总分 3-4：启动 1-2 个 subagents。
- `[DEFAULT]` 总分 5 以上：仅在边界清晰时启动 2-3 个 subagents；不得仅因风险高而增加可写代理数量。

## 一主一辅默认模式

- `[DEFAULT]` 模板、文档、生成器、渲染器、脚本、配置或中小型代码改动，默认“一主一辅”；只有纯文本微调、无验证面且无一致性风险时才豁免。
- `[DEFAULT]` 主线程负责关键路径实现、写入边界、结果集成、最终验证与交付，并在辅线程运行时继续推进可执行步骤。
- `[DEFAULT]` 辅线程负责只读首轮审查、单一风险主题核对、产物一致性检查或有界文档/测试建议。
- `[MUST]` 辅线程默认只读；除非主代理明确独立写入边界，否则不得与主线程争抢同一文件。
- `[MUST]` 若多个可写 subagents 并行，必须按文件、目录或模块划分所有权；无法划清时只允许一个可写代理，其余只读。

## 上下文与成本控制

- `[MUST]` 向 subagent 传递最小必要包：目标、边界、相关文件集、必要约束、输出格式。
- `[MUST NOT]` 不把整段会话历史、全量计划、无关文件列表或大段日志广播给多个 subagents。
- `[MUST]` 多个 subagents 共享背景时，先由主代理压缩成短摘要，再按职责补充差异化约束。
- `[MUST]` 首次委派默认显式使用 `fork_turns: "none"` 并提供最小任务包；只有依赖最近决策时才使用有界正整数，确需完整会话历史时才使用 `fork_turns: "all"`。
- `[MUST]` 若同一批背景预计被多个子代理重复消费，先重新评估是否真的需要多个子代理。
- `[DEFAULT]` 首批默认 1 个 subagent；存在两个清晰独立旁路时使用 2 个；只有跨模块边界稳定且收益明确时使用 3 个，不默认占满全部并发槽位。
- `[DEFAULT]` subagent 不继续委派其他 subagent；确需二级分发时由主代理明确授权并控制总并发预算。

最小任务包固定包含：

```text
目标：
范围：
已知入口：
允许读取：
禁止事项：
验证要求：
输出格式：
```

## 宿主能力与角色热集

- `[MUST]` 委派前确认角色在当前宿主可调用；仓库存在同名 TOML 只代表资产可安装，不代表本轮宿主已暴露该角色。
- `[DEFAULT]` 常规任务优先从核心热集选择：`explorer`、`worker`、`reviewer`、`debugger`、`test-automator`、`frontend-developer`、`backend-developer`、`browser-debugger`、`security-auditor`。
- `[DEFAULT]` 只有明确命中框架、语言、基础设施或业务专项时才选择扩展角色；名称不可用时回退到热集中最接近的通用角色。
- `[MUST NOT]` 不因相近角色名称连续试错；一次角色不可用后，优先回退通用角色或由主代理本地完成。

## 模型与推理强度

- `[MUST]` 子代理模型控制优先级：平台/系统固定绑定 > 角色级固定绑定 > 运行时 `model` / `reasoning_effort` > 子代理默认配置。
- `[DEFAULT]` 首轮审查、范围收敛、只读探索、需求整理和上下文压缩优先 `gpt-5.6-terra` + `medium`；边界明确且速度优先时可降为 `low`。
- `[DEFAULT]` 常规实现、测试补全、构建修复优先 `gpt-5.6` + `medium`；架构、安全、支付、生产事故和深度调试优先 `gpt-5.6` + `high`。
- `[MUST]` `xhigh` 仅用于已收敛问题的裁决阶段，不用于首轮探索、宽范围审查或开放式研究。
- `[MUST]` 升级到 `xhigh` 前，范围必须收敛到有界文件集、单一风险主题、单一故障链路或单一架构决策点。
- `[MUST]` 同一用户任务默认最多 1 个 `xhigh` 子代理；确需多个时在交付中说明边界差异与收益。
- `[MUST]` 仅 `debugger`、`security-auditor`、`penetration-tester`、`architect-reviewer`、`incident-responder`、`devops-incident-responder`、`fintech-engineer`、`payment-integration`、`microservices-architect`、`llm-architect` 默认允许运行时升级到 `xhigh`。
- `[DEFAULT]` `reviewer`、`security-engineer`、`cloud-architect`、`sre-engineer`、`database-administrator`、`performance-engineer`、`api-designer`、`quant-analyst`、`mlops-engineer` 仅在复杂收敛场景下条件性升级到 `xhigh`。

## Spawn、等待与降级

- `[MUST]` 首次委派某个 subagent 时使用最小兼容调用，仅显式传入最小任务包和 `fork_turns`；不要默认叠加模型覆盖、推理覆盖或复杂格式控制。
- `[MUST]` 区分创建阶段失败和已创建但未产出结果；前者优先检查调用链、参数兼容、会话资源，后者再等待或缩小边界。
- `[DEFAULT]` `Agent spawn failed`、会话配额不足、参数版本不兼容、响应 schema 不兼容等归类为工具层或资源阶段问题。
- `[MUST NOT]` 同一范围连续两次工具层兼容故障后，不继续机械更换审查代理；改为本地复查、构建/测试或更小范围重派。
- `[MUST]` 仅在下一步确实依赖 subagent 结果时等待；否则继续推进主线程。
- `[MUST]` 并行旁路任务应先连续发起，再在明确集成节点统一等待；不得 `spawn -> wait -> spawn` 串行调度。
- `[DEFAULT]` 审查类 subagent 要求首轮高信号 findings；范围过大时优先缩小到最高风险文件集或切换为单一风险主题。
- `[DEFAULT]` 构建、测试、浏览器或外部服务等待是优先委派窗口；等待结束后才启动的重复审查通常由主代理本地完成。

## 选型路由

- `[MUST]` 选型顺序：核心热集 -> 明确专项 -> 通用回退；不得仅因名称相近跳过本地分析直接委派。
- `[DEFAULT]` 只读定位用 `explorer`，明确小实现用 `worker`，通用审查用 `reviewer`，调试用 `debugger`，测试用 `test-automator`。
- `[DEFAULT]` 前后端实现分别用 `frontend-developer`、`backend-developer`；跨职责任务只有在共享契约稳定后才选择 `fullstack-developer` 或拆分专项角色。
- `[DEFAULT]` 安全、浏览器、架构、平台或具体语言框架仅在任务明确命中时选择对应专项角色。

## 常用组合

- `[DEFAULT]` 通用代码修改：主代理推进实现；存在真实等待窗口或独立风险面时，并行 1 个 `reviewer`。
- `[DEFAULT]` 代码修改且需要补测试：测试入口可提前确定时并行 `test-automator`，否则由主代理先稳定接口。
- `[DEFAULT]` 多职责新功能：主代理先收敛共享契约，再按独立模块分发 1-2 个实现或验证职责面。
- `[DEFAULT]` 安全敏感改动：主代理控制写入边界，可并行 1 个只读 `security-auditor`；不得让多个写入代理同时修改关键路径。
- `[DEFAULT]` 复杂缺陷排查：主代理推进最短故障链，仅把互不依赖的日志、配置或代码证据主题委派出去。

## 输出契约

- `[MUST]` 所有 subagent 输出应包含：结论、涉及文件、关键原因、风险或未覆盖项；如有代码修改，列出修改文件路径。
- `[MUST]` 审查类输出 findings first，按严重度排序；未发现问题时明确写出已审查范围、“未发现高信号问题”和最高风险未覆盖区域。
- `[MUST]` 审查类因工具层问题未纳入时，主代理交付中说明故障归类、替代验证方式和覆盖范围影响。
- `[MUST]` 实现类输出实现结果、改动范围、验证方式与残余风险；规划类输出任务拆分、依赖关系、关键路径与建议分发方式。

## 审查委派模板

```text
请只审查以下有界范围，不要扩展到整个仓库：

- files:
  - <path-1>
  - <path-2>
- change summary: <一句话说明本次改动>
- focus: correctness | regression | security | missing tests
- scope limit: 仅限上述文件；只有在确认 finding 必须引用某个直接依赖时，才允许最小化查看该依赖

输出要求：
1. findings first，按严重度排序
2. 每条 finding 必须包含文件定位与原因
3. 若未发现高信号问题，明确写出“在上述有界范围内未发现高信号问题”
4. 最后补 1 条“最高风险未覆盖区域”，若无则写“无”
```

## 风险与中断边界

- `[MUST]` 高风险业务动作、敏感信息、认证授权、支付、生产配置、客户数据相关任务，subagent 仅处理最小必要范围，最终决策由主代理把关。
- `[MUST]` 若 subagent 需要接触潜在敏感上下文，主代理先脱敏或裁剪输入。
- `[MUST NOT]` 不为分发方便把敏感配置、全量日志、无关源码大范围下发给多个 subagents。
- `[STOP]` 若计划会导致多个 subagents 同时修改同一关键路径文件、敏感信息扩散、高风险动作无人复核，或连续两轮分发仍无法收敛，必须停止扩大发散并收敛策略。
