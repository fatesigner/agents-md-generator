# 长任务、上下文与自动化专项规则

本文件按需加载。任务需要复杂 Prompt、长线程、跨轮次状态、Steer/Queue、模型与速度选择、automation 或 artifact 审阅时使用。

## 任务契约

复杂任务优先使用以下最小结构；只保留会改变行为的字段，不为简单任务机械填满模板。

```text
目标：
<最终需要完成什么>

上下文：
<项目、目录、错误、文档、数据源或真实入口>

约束：
<必须保持什么；不能扩大到哪里>

完成标准：
<测试、运行行为、浏览器证据、部署回读或文件验收>

授权边界：
<可自动执行什么；哪些外部、生产、破坏性或不可逆动作前必须确认>

输出：
<结论、改动文件、验证证据、残余风险或指定格式>
```

- `[MUST]` 先描述结果和完成标准；只有过程本身影响安全、正确性或审计时才规定步骤。
- `[MUST]` 用户显式提供的路径、值、目标和边界必须保留；隐式选择使用判断标准，不使用僵硬关键词映射。
- `[DEFAULT]` 简单任务仅保留目标、关键约束和完成标准。

## 上下文载体分层

| 内容 | 默认载体 |
| --- | --- |
| 一次性要求、当前任务边界 | 当前 prompt / thread |
| 持续工作流的当前状态 | durable thread + 短 checkpoint |
| 稳定仓库规则、命令和验证标准 | `AGENTS.md` |
| 模型、权限、MCP、hook 和 feature 默认值 | `.codex/config.toml` 或全局配置 |
| 重复执行的完整流程、脚本和参考资料 | skill |
| 实时外部数据和授权操作 | plugin、MCP 或 connector |
| 周期性检查、提醒或监控 | automation |
| 必须机械执行的生命周期约束 | hook |

- `[MUST]` 不把动态项目状态、每日进度或临时发现持续写入 `AGENTS.md`。
- `[MUST]` 影响实现的长期决定写入可审阅、可 diff 的项目文档；不得只依赖隐式对话记忆。
- `[DEFAULT]` 临时运行记录使用项目既有 `.codex/` 目录；需要团队长期共享的决定使用仓库跟踪文档。

## 长任务 checkpoint

在需求收敛、实现完成、验证完成或外部协调前后记录短 checkpoint：

```text
当前目标：
已经完成：
验证证据：
未验证/阻塞：
关键决定：
下一步：
需确认动作：
```

- `[MUST]` checkpoint 只保留仍会影响后续决策的事实，不复制全量日志、命令输出或探索过程。
- `[DEFAULT]` 长线程出现明显无关上下文、冲突或重复澄清时，用 checkpoint 作为新线程交接摘要。

## Steer、Queue 与新线程

- **Steer**：当前方向已经错误、缺少关键事实或需要立即改变本轮行为。
- **Queue**：当前步骤可以继续，但完成后需要执行下一步。
- **New thread**：新目标与当前任务低相关，或继续会显著污染主线程上下文。

- `[MUST]` Steering 只传递变化的事实和方向，不重复发送整个原 Prompt。
- `[MUST]` Queue 明确前置完成条件，不把依赖当前结果的动作伪装成可并行工作。
- `[DEFAULT]` 新线程使用 checkpoint 交接，不复制全量历史。

## 模型、推理与速度

- `[DEFAULT]` 模糊、跨模块、验证密集或高风险任务使用宿主当前推荐的高能力模型；只读扫描、资料整理和轻量 subagent 使用快速、低成本模型。
- `[MUST]` 先以当前有效 reasoning 作为基线；代表任务比较同一档和低一档后再调整。
- `[MUST NOT]` 不把最高 reasoning、Fast mode 或高价 service tier 设为所有任务的默认值。
- `[DEFAULT]` Fast mode 只用于用户正在等待的交互关键路径；后台批量、自动化和高吞吐任务优先控制成本。
- `[MUST]` 模型、reasoning 或速度策略的优化以真实成功任务为基准，同时比较质量、端到端耗时、首次实质结果、重试、token/credit 和返工。

## Automation

- `[MUST]` 只自动化已经稳定、可重复、结果易审阅的循环。
- `[MUST]` 每个 automation 必须定义：
  - 数据源或目标对象
  - 周期、触发或状态变化条件
  - 允许执行的只读或本地动作
  - 停止条件
  - 输出和通知条件
  - 需要人工审批的动作
- `[DEFAULT]` 需要保留当前对话上下文的持续跟进使用 thread heartbeat；独立、固定周期的跨线程任务使用 standalone schedule/cron。
- `[MUST NOT]` automation 不得静默发送消息、push、merge、部署、付款、提交订单、提交审批或执行其他不可逆动作。
- `[DEFAULT]` 状态未变化时不重复输出同一报告；只在变化、失败、阻塞或需要判断时通知。

安全示例：

```text
在当前发布窗口内，每 30 分钟检查指定 PR、CI 或部署状态。
仅在状态变化、失败或需要人工决定时汇报。
不要重跑、合并、push 或发布。
条件满足或发布窗口结束后停止。
```

## Artifact 审阅

- `[MUST]` 让完成标准匹配产物表面：
  - 代码：目标测试、静态检查、diff review
  - UI：真实渲染、关键状态、响应式、console/network
  - PDF/演示文稿：渲染后检查裁切、重叠、字体、分页和清晰度
  - 表格：列头、公式、排序、异常值和编辑结果
  - 部署：运行副本、进程/容器/API 回读，而非仅构建成功
  - 数据库：受控查询结果和权限边界，而非仅 ping 成功
- `[MUST]` 工具调用成功不等于用户目标完成；最终结果必须回到完成标准验收。
