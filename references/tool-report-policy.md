# 工具调用简报专项规则

## 工具调用简报格式

- `[MUST]` 代码修改、多工具调用、外部检索、用户要求审计留痕或 prompt 明确要求工具简报时，在答复末尾追加以下简报模板（可省略无关项，不可省略已调用项）。

```text
工具调用简报
- PyMuPDF: 目的；关键参数；结果摘要。
- context7: 目的；关键参数；结果摘要。
- exec_command: 目的；关键参数；结果摘要。
- 重试与降级: 是否发生；原因；替代方案；影响范围。
```

- `[MUST]` 工具调用简报中应记录所有已调用的 MCP 工具、Python 与文档处理工具、以及其他工具。
- `[MUST]` 若当前答复中未调用任何工具，或所有候选简报项均因省略规则被移除，则整段“工具调用简报”直接省略，不输出标题、空列表或“无”。
- `[DEFAULT]` 简单只读分析、范围确认或有界审查任务，可省略完整工具调用简报，或用 1-3 行说明关键工具、验证状态和未覆盖风险。
- `[MUST]` 除 `重试与降级` 与本节明确允许的汇总项外，工具调用简报中的每个具体工具都必须单独占一行，不得将多个具体工具合并在同一行。
- `[MUST]` 无论工具来自 MCP、Python 与文档处理工具，还是其他工具，简报中的每一行都必须直接以最终具体工具名开头，不得保留类别名前缀；但 `serena` 允许按 MCP 工具族汇总为单独一行，统一写为 `serena`，不展开列出 `mcp__serena__activate_project`、`mcp__serena__search_for_pattern` 等具体子调用。
- `[MUST]` 工具简报行必须至少包含“具体工具名 + 用途/目的 + 结果摘要”。
- `[DEFAULT]` 工具简报行的推荐格式为“具体工具名: 用途/目的；输入摘要/关键参数/处理对象（三选一或组合）；结果摘要。”。
- `[DEFAULT]` `serena` 汇总行推荐写法为“`serena`: 用途/目的；处理对象或目标子项目；结果摘要。”；仅在与结论直接相关时补充“已激活目标子项目”“做了符号检索/引用分析/符号级编辑”等高层动作，不逐条罗列具体 MCP 方法名。
- `[DEFAULT]` 若“关键参数”对当前工具没有信息价值，可改写为“输入摘要”或“处理对象”，也可省略；不得为凑格式填写低价值占位内容。
- `[DEFAULT]` 工具调用简报默认不强制记录模型与推理强度；仅当这些信息会影响结果质量、成本、时延、结论可信度或后续复盘时再补充。
- `[MUST]` 若任务使用了 subagent，且显式指定了模型或 `reasoning_effort`，必须在对应简报行中记录。
- `[MUST]` 若显式指定了非默认推理强度，尤其是 `high` 或 `xhigh`，必须在工具调用简报中记录。
- `[MUST]` 未显式指定模型或推理强度时，不得在工具调用简报中臆测；可写“未显式指定，使用默认配置”。
- `[DEFAULT]` 对 subagent 的工具简报行，可使用如下格式：
  - `spawn_agent(<agent_type>)`: 用途/目的；模型 `gpt-5.6`；推理强度 `xhigh`；结果摘要。
  - `spawn_agent(<agent_type>)`: 用途/目的；未显式指定模型/推理强度，使用默认配置；结果摘要。
- `[DEFAULT]` 仅在确有必要时，在工具简报行中补充解释器路径、运行环境或版本信息。
- `[DEFAULT]` `重试与降级` 仅在实际发生重试、降级、替代执行或失败回退时才显示；未发生时直接省略，不输出“无”。
