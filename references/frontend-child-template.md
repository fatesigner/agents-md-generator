## 前端改动边界

- `[MUST]` 页面级逻辑优先放在 `[页面目录集合]` 及相邻业务目录。
- `[MUST NOT]` 把页面逻辑散落到 `[共享目录集合]`。
- `[MUST]` 路由改动优先收敛在 `[路由目录]`；状态管理改动优先收敛在 `[状态目录]`。
- `[MUST]` 通用能力、公共组件、共享工具优先放在 `[共享目录集合]`；新增前先确认是否已有同类实现。
- `[MUST]` 可复用组件放共享目录；页面私有组件可留页面目录并使用 `components`、`parts` 命名。
- `[MUST NOT]` 页面局部目录使用 `shared` 命名。
- `[MUST]` 接口请求定义收敛在 `[接口目录]` 或现有 API 封装层。
- `[MUST NOT]` 在页面组件直接散写请求实现。
- `[MUST]` 涉及环境、模式或构建差异改动时，优先检查 `[关键前端配置文件集合]`。
- `[MUST NOT]` 未经明确需求调整构建、Babel、PostCSS、Stylelint、OpenAPI 生成和测试链路配置。
- `[MUST]` 前端实现的可读性、复杂度与抽象边界继承全局“编码行为四原则”。

## 接口与类型联动

- `[MUST NOT]` 在前端引入同义字段名。

- `[MUST NOT]` 在页面组件重复声明相同结构。

## 路由与状态边界

- `[MUST]` 路由定义、导航守卫、页面准入控制、路由权限逻辑收敛在 `[路由目录]` 或既有路由层。
- `[MUST]` 页面局部状态留在页面或相邻模块；跨页面共享状态收敛在 `[状态目录]`。
- `[MUST NOT]` 在页面组件散写路由鉴权、菜单激活、全局缓存恢复、跨页面状态编排。
- `[MUST]` 涉及登录态、租户切换、权限刷新、菜单同步、路由回跳改动时，明确受影响路由入口、状态键、恢复路径。
- `[DEFAULT]` 页面容器与编排代码允许承担有限组合职责，但需保持数据流与状态边界清晰。

## 异步错误处理约定

- `[MUST]` 根据异步逻辑职责选择项目已使用的错误处理方式或 `try/catch/finally`，不机械统一写法。
- `[MUST]` 当一次交互包含多个异步步骤，或存在统一收尾动作（如 loading、按钮禁用、提交态恢复、路由跳转后处理）时，使用 `try/catch/finally`。
- `[MUST]` 当存在“无论成功失败都必须执行”的收尾动作时，使用 `finally` 承担收尾职责。
- `[DEFAULT]` 当代码仅包含单个异步请求，失败后只需本地分支处理、无需统一 cleanup 时，可使用条件判断、Promise 错误处理或项目已使用的轻量封装。
- `[MUST NOT]` 已存在外层 `try/catch/finally` 时，不为同一异步链路机械再包一层错误处理；若无明显可读性收益，应保持单一控制流。
- `[MUST NOT]` 不得使用异常作为常规流程控制手段；高频、可预期的失败分支优先使用条件判断而非 `throw/catch`。
- `[DEFAULT]` 页面按钮事件、表单提交、初始化加载、上传下载、登录登出等 UI 交互闭环，优先使用 `try/catch/finally`。
- `[DEFAULT]` 单次查询、可选资源探测、失败后直接 fallback 的短链路读取，可优先使用清晰的局部分支处理。
- `[MUST]` 若函数仍需让上层感知失败，`catch` 后必须重新抛出，或改为不在当前层捕获；不得在可复用业务动作中无说明地吞掉异常。
- `[DEFAULT]` 若函数只是页面内部事件处理器，且已在当前层完成用户提示、状态恢复与收尾，可在当前层终止异常传播。

## 代码风格与格式化执行

- `[MUST]` 若项目存在 ESLint/Prettier 配置或对应脚本，新增或修改前端代码后必须至少执行一次与改动匹配的自动修复；涉及导入顺序、未使用导入、可自动修复规则时，优先执行 ESLint auto-fix，而不是仅执行 Prettier 格式化。
- `[MUST]` 若项目存在 ESLint/Prettier 配置或对应脚本，生成新文件后必须立即执行一次针对该文件的 lint/fix 或等价自动修复，再继续后续实现。
- `[MUST]` 优先使用 `package.json` 已定义脚本执行自动修复、格式化与校验，不自行发明命令。
- `[DEFAULT]` 若项目使用 VS Code 且 ESLint 扩展已接管代码操作，`Fix all auto-fixable problems` / `source.fixAll.eslint` 视为与 `eslint --fix` 等价的自动修复入口。
- `[DEFAULT]` 自动修复与格式化命令优先级：
  - `npm run lint -- --fix`（或等价脚本）
  - `eslint . --fix` 或针对改动文件的最小化 `eslint --fix`
  - `npm run format`（或等价脚本）
  - 若无脚本，仅对改动文件执行最小化自动修复/格式化命令
- `[MUST]` 若项目使用 `simple-import-sort/imports`、`import/order` 或同类 ESLint 可修复规则，导入顺序应通过 ESLint auto-fix 修复，不得期待 Prettier 单独产出正确顺序。
- `[MUST]` 若存在 `.eslintrc*`、`eslint.config.*`、`.prettierrc*`、`prettier.config.*`，必须以项目本地配置为准，不使用全局默认风格。
- `[MUST]` 若项目未配置 ESLint/Prettier 或无可用脚本，不得臆造命令或临时安装依赖；需在交付中说明现状并执行可用的最小验证。
- `[MUST]` 默认仅格式化本次改动文件，避免无关全仓改写。
- `[MUST]` 格式化或修复命令失败时，在交付中说明失败原因、已尝试命令与剩余风险。

## 样式与前端实现约定

- `[MUST]` 当前项目已使用 `[样式与质量工具]`；样式实现优先遵循既有页面和模块写法。
- `[MUST]` 周边代码已使用 utility class 或项目样式工具时可沿用。
- `[MUST NOT]` 为单点改动强行切换样式组织方式。
- `[MUST]` 涉及主题、全局样式或设计令牌改动时，优先检查 `[样式主题目录]` 与样式入口。
- `[DEFAULT]` 若项目使用 CSS Modules，原始 class 名仍优先使用 `kebab-case`；仅在 JS/TS 访问样式映射对象时，按项目既有约定决定是否使用 camelCase 映射，不反向要求把原始类名改为 camelCase。
- `[DEFAULT]` 若项目未定义更细规则，组件根 class 建议与组件语义保持一致，并优先使用稳定块名，如 `user-card`、`settings-panel`、`upload-dialog`。
- `[DEFAULT]` 若项目未定义更细规则，组件内部层级优先采用 BEM 或等价的稳定层级命名，避免在同一组件内混用多套命名风格。
- `[MUST NOT]` 在同一组件或页面局部同时混用大段 utility class 命名语义与自定义业务 class 命名语义，除非项目既有模式明确如此组织。
- `[DEFAULT]` 若项目周边代码以 utility class 为主，自定义 class 应优先承担“语义块”或“状态钩子”职责，不重复封装已由 utility class 直接表达的简单表现样式。
- `[DEFAULT]` 若项目存在设计系统 token、主题变量或样式前缀约定，新增 class、data-attribute、主题变量和样式入口优先沿用既有前缀与分层，不私自新增平行命名体系。
- `[MUST]` 新增类型定义优先放在 `[类型目录]` 或既有类型文件。
