# Agent 运行效率专项规则

## 目标与边界

- `[MUST]` 优化目标按优先级为：端到端壁钟时间、首次实质结果时间、正确性与验证覆盖；subagent 启动率仅用于解释调度行为。
- `[MUST]` 不以降低必要安全门槛、跳过目标模块验证或扩大敏感上下文传播来换取速度。
- `[DEFAULT]` 不引入常驻遥测服务；仅在项目已有留痕约定或用户要求性能评估时记录脱敏摘要。

## 任务分档

| 任务形态 | 默认并发 |
| --- | --- |
| 路径明确、预计 60 秒内、无外部等待 | 主代理本地完成 |
| 路径明确且存在构建、测试、浏览器或外部等待 | 等待前启动 1 个只读旁路 |
| 一个未收敛入口或单一证据主题 | 主代理推进关键路径，1 个 `explorer` 旁路 |
| 两个独立模块且共享契约稳定 | 1-2 个 subagents，按模块划分所有权 |
| 三个以上独立模块且整合成本可控 | 最多 3 个 subagents，主代理保留集成职责 |
| 强串行调试、共享状态或敏感关键路径 | 0-1 个只读旁路 |

- `[DEFAULT]` 60 秒是初始阈值，应根据本机和宿主的真实 P50/P90 数据调整，不作为正确性豁免条件。

## 临界路径与等待窗口

- `[MUST]` 主代理推进当前阻塞路径，不把关键路径整体外包后空等。
- `[MUST]` 独立旁路应先连续发起，再在明确集成节点统一等待；禁止 `spawn -> wait -> spawn` 串行调度。
- `[DEFAULT]` 构建、测试、lint、typecheck、浏览器、下载和外部服务等待是优先并行窗口。
- `[DEFAULT]` 等待结束后才开始且与主代理重复的审查，通常由主代理本地完成。

## 工具往返控制

- `[DEFAULT]` 互不依赖的精确搜索、文件存在性、只读元数据和验证命令同批并行。
- `[MUST]` 有写入依赖、共享状态、相同文件所有权或破坏性风险的步骤保持串行。
- `[DEFAULT]` 一次精确定位、一次不重叠局部读取、一次职责面 patch、一次验证批次、一次集成等待；缺证据时才追加下一批。
- `[MUST NOT]` 不为填满并发槽位重复读取同一上下文或运行等价验证。

## 模型与上下文成本

- `[DEFAULT]` 主代理普通任务默认使用 `high`；宿主支持独立模型配置时，入口定位、范围收敛和短只读旁路可使用快速模型与 `low` 或 `medium`。
- `[MUST]` 复杂、模糊或高风险任务在 Plan mode 使用 `xhigh`；根因、约束和方案确认后，机械实现与常规验证恢复为 `high`。
- `[MUST]` 生产或不可逆写入、认证授权或支付安全、破坏性 schema 变更、跨服务一致性或并发、架构迁移、关键证据冲突任一硬门槛，触发下一轮或 Plan 阶段使用 `xhigh`。
- `[MUST]` 未命中硬门槛但同时存在至少两个复杂度信号时使用 `xhigh`：需求多义、跨三个以上模块或运行层、复杂状态机或并发、缺少直接验证、两条实质性调查路径失败。
- `[MUST]` `high` 下出现两次实质性错误路径或遗漏关键约束时，下一轮提升到 `xhigh`；同类失败连续三次时按全局失败阈值停止重试。
- `[MUST NOT]` 不因构建、测试、浏览器或外部服务等待时间较长而提高 reasoning；等待时间不是推理复杂度信号。
- `[MUST NOT]` 不把 `xhigh`、Fast mode 或高价 service tier 设为所有任务的全局默认值。
- `[DEFAULT]` Fast mode 只用于用户正在等待的交互关键路径；后台批量、自动化和高吞吐任务优先控制成本。
- `[MUST]` 调整模型、reasoning 或速度模式时，先保留当前有效基线，再在同一批代表任务上比较同一档与低一档；不得以单次主观体验宣称提速。
- `[MUST]` subagent 默认 `fork_turns: "none"` 并使用最小任务包；只有任务依赖近期或完整决策历史时才扩大上下文。

## 度量与 A/B 验证

建议记录：

- P50/P90 端到端完成时间；
- 首次实质结果时间；
- 主代理空等时间占比；
- subagent 结果采纳率与 spawn 失败率；
- 重复读取、重复验证和共享写入冲突次数；
- 平均每任务 subagent 数与实际 speedup；
- token/credit 消耗、返工次数与最终验证通过率。

- `[MUST]` 性能留痕写入目标项目既有本地产物目录；未声明时使用 `.codex/perf/`，不得包含 prompt 全文、源码全文、日志全文或敏感数据。
- `[DEFAULT]` 单条记录仅保留任务类型、范围等级、耗时、subagent 数、结果是否采纳、等待耗时、失败数和验证类型。
- `[DEFAULT]` 以 20-50 个代表性任务比较现行策略与自适应策略；分别覆盖局部小修、普通功能、跨模块功能和复杂调试。
- `[MUST]` 静态规则、模板体积和隔离同步只能证明配置正确；没有真实任务样本时不得宣称已获得实际时延提升。
