### Serena 与 code-index 使用约定

- `[MUST]` 在多项目仓库中，`serena` 的语义是“基于当前激活的项目根目录，选择一个可用的语言服务上下文”，不是“自动将整个仓库拆分为多个语言服务并自动切换前后端上下文”。
- `[MUST]` 使用 `serena` 时，必须先确认目标子项目目录，并按该路径显式激活；跨前后端、跨子项目或从仓库根切换到子项目时，必须重新激活。
- `[MUST]` `serena` 在任一时刻只针对一个当前激活的子项目上下文工作；不得直接沿用上一个子项目的 `serena` 结果推断另一个子项目的实现。
- `[DEFAULT]` 已知目标子项目、目标符号、目标语言上下文时，优先使用 `serena` 做符号检索、引用分析和符号级编辑。
- `[DEFAULT]` 仅知道关键词、文件名、报错文本、接口路径、配置项或文案片段时，优先使用 `code-index` 做全文、关键词、文件或代码模式搜索。
- `[MUST]` 当目标位置尚不明确时，先用 `code-index` 在最小必要范围内收敛到文件、目录或候选符号，再切换到 `serena` 做精确分析或编辑。
- `[MUST NOT]` 在仅需关键词或文件定位时，直接使用 `serena` 对整个多项目仓库做模糊探索。
- `[MUST NOT]` 在已明确目标符号且已知目标子项目的情况下，继续仅依赖 `code-index` 做低精度文本匹配分析而不切换到 `serena`。
- `[MUST]` 若任务涉及多个子项目，应分别收敛范围、分别激活对应路径，再汇总结论；不得在未切换激活路径的情况下直接推断另一子项目内部实现。
- `[MUST]` 若 `serena` 因激活目录不正确、上下文不匹配或目标不在当前项目根内而无法可靠工作，应回退到 `code-index` 重新定位范围。

### 项目执行上下文

- `[MUST]` 对任一项目目录、子项目目录或模块目录执行依赖本地依赖、本地配置、插件解析、虚拟环境、项目级脚本或工具链上下文的命令时，必须在目标目录执行，或显式将 `workdir` 设置为该目标目录；当仓库根目录不等于实际执行目录时，不得默认在仓库根目录直接运行。
- `[MUST]` 若命令的依赖解析、配置加载、插件发现、虚拟环境选择、项目文件定位或脚本行为受当前工作目录影响，则视为“依赖项目执行上下文”的命令。
- `[DEFAULT]` 典型命令包括但不限于：前端的 `prettier`、`eslint`、`stylelint`、`jest`、`vite`、`tsc`、`npx <tool>`、`npm run <script>`；Python 的 `pytest`、`ruff`、`mypy`、`alembic`；Java/Gradle/Maven 的 `gradlew`、`mvn <goal>`；Rust 的 `cargo <cmd>`；Go 的 `go test`、`golangci-lint`；.NET 的 `dotnet build`、`dotnet test`。
- `[DEFAULT]` 若命令目标为某个子项目目录或模块目录，默认工作目录使用对应目录；其他项目或模块同理，默认使用其项目根目录；除非仓库脚本、workspace 配置、构建入口或项目文档明确要求从仓库根目录执行。
- `[MUST NOT]` 未确认执行上下文前，不在仓库根目录直接执行目标项目的 `npx <tool>`、裸工具命令、项目脚本或其他依赖本地解析上下文的命令。
- `[DEFAULT]` 若仓库已正确配置 workspace、多模块统一入口或根级调度脚本，且项目文档明确说明可从根目录安全触发，则可按项目约定执行，例如 `npm --workspace`、`pnpm --filter`、`yarn workspace`、`cargo -p`、`go test ./subdir/...`、`dotnet <cmd> <project.csproj>`。
- `[MUST]` 出现“找不到插件”“找不到配置”“找不到本地依赖”“找不到虚拟环境”“模块解析失败”“项目文件定位失败”等问题时，优先检查当前工作目录、`workdir`、目标目录依赖是否已安装、配置文件定位方式以及项目文档约定；不得先假设为全局依赖缺失或直接建议全局安装。
- `[MUST NOT]` 不通过全局安装 `prettier`、`eslint`、`stylelint`、`typescript`、`pytest`、`ruff` 等方式规避目标项目的本地依赖或本地工具链解析问题，除非用户明确要求且已说明风险。
